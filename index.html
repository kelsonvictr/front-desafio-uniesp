01
Componentes e JSX
Aula 01 · A unidade fundamental do React

Um componente é um pedaço de tela que dá pra reutilizar. Em React, a forma mais comum é o componente funcional: uma função JavaScript que retorna o que aparece na tela (em JSX, uma "mistura" de HTML com JavaScript).

Pensa numa peça de Lego

Cada componente é uma pecinha. Você monta ela uma vez e usa em vários lugares do projeto. O App é a peça-mãe que junta todas as outras.

src/components/Saudacao.jsx JSX 
const Saudacao = () => {
  return (
    <div>
      <h1>Olá, turma do React!</h1>
    </div>
  )
}

export default Saudacao
⚡ Olha o pulo do gato: o atalho "rafce"

Em aula a gente cria componente digitando rafce no editor e apertando Tab. O snippet já cuspe o componente pronto, no formato de arrow function, com o export default no final. Por isso todos os exemplos daqui pra frente usam const X = () => { } em vez de function X() { }.

O nome rafce vem de React Arrow Function Component Export. Mas pra você decorar mais fácil, eu brinco em aula que rafce é apelido de "Rafael do Ceará" 😄.

Pra ter esse atalho no VS Code, instale a extensão ES7+ React/Redux/React-Native snippets (autor: dsznajder). Funciona também no IntelliJ se você tiver o plugin equivalente instalado.

E pra usar esse componente em outro lugar (por exemplo no App.jsx):

src/App.jsx JSX 
import Saudacao from './components/Saudacao'

const App = () => {
  return (
    <div>
      <Saudacao />
      <Saudacao />
      <Saudacao />
    </div>
  )
}

export default App
JSX em 3 regras

1️⃣ O nome do componente começa com letra maiúscula (Saudacao, não saudacao).

2️⃣ Toda tag precisa fechar: <img />, <br />, <input />.

3️⃣ Pra colocar JavaScript no meio do HTML, use chaves { }. Ex.: <h1>{nome}</h1>.

Esse { } é o que a gente chamou de template expression. Tudo que está dentro das chaves é JavaScript de verdade:

exemplo.jsx JSX 
const nome = 'Maria'
const idade = 25

return (
  <div>
    <h1>Olá, {nome}!</h1>
    <p>Você tem {idade} anos</p>
    <p>Em 10 anos, terá {idade + 10}</p>
  </div>
)
💡
Boa prática: um componente por arquivo, dentro de src/components/. Nome do arquivo igual ao nome do componente (Saudacao.jsx contém const Saudacao = () => { }).

02
Eventos com onClick
Aula 02 · "O que acontece quando o usuário clica"

Eventos são tudo que o usuário faz: clicar, digitar, passar o mouse, enviar um formulário. No React, a gente liga uma função a um evento usando atributos como onClick, onChange, onSubmit.

É como uma campainha

O botão é o botão da campainha. A função (handleClick) é quem atende e diz "tá, fulano apertou, deixa eu fazer X". Sem a função ligada, a campainha só apita pro vazio.

MeuBotao.jsx JSX 
const MeuBotao = () => {

  const handleClick = () => {
    console.log('O botão foi clicado!')
    alert('Oi! Você clicou.')
  }

  return (
    <div>
      <button onClick={handleClick}>
        Clique aqui
      </button>
    </div>
  )
}

export default MeuBotao
⚠️
Cuidado com os parênteses! Veja a diferença:
  • onClick={handleClick} ✅ — passa a função, o React chama no clique
  • onClick={handleClick()} ❌ — JÁ chama a função na hora de renderizar

Se a função é bem curtinha (1 linha), dá pra escrever inline com arrow function:

BotaoCurto.jsx JSX 
<button onClick={() => alert('Cliquei!')}>
  Clique
</button>
📝
Sintaxe da arrow function: () => { ... }. Você digita = seguido de >. Se sua IDE mostrar como uma "seta única", são as ligatures da fonte. Mas no código de verdade são dois caracteres separados.

03
useState — o estado do componente
Aula 02 · O primeiro hook que você vê na vida

Uma variável comum, quando muda, não atualiza a tela. O React precisa de uma forma especial de guardar valores: o useState. Ele guarda o valor E avisa o React quando esse valor mudou, pra ele redesenhar a tela.

É uma caixinha com aviso embutido

Uma variável normal é uma caixinha com um valor dentro. O useState é a mesma caixinha, mas quando você troca o que tá dentro, ela solta um alarme que diz "ô React, mudei aqui, redesenha a tela!".

Contador.jsx JSX 
import { useState } from 'react'

const Contador = () => {

  const [contador, setContador] = useState(0)

  return (
    <div>
      <h1>Você clicou {contador} vezes</h1>
      <button onClick={() => setContador(contador + 1)}>
        Incrementar
      </button>
    </div>
  )
}

export default Contador
A linha mágica

const [contador, setContador] = useState(0);

📦 contador — o valor atual (pra ler/exibir na tela)

🔧 setContador — a função pra trocar o valor (e disparar o redesenho)

🎯 useState(0) — o valor inicial (no caso, zero)

🚫
Nunca, jamais, em hipótese alguma faça contador = contador + 1. O React não vai perceber a mudança e a tela não atualiza. Sempre use a função setContador(novoValor).

useState também guarda arrays e objetos:

ExemplosState.jsx JSX 
// string
const [nome, setNome] = useState('')

// boolean
const [logado, setLogado] = useState(false)

// array (lista de coisas)
const [produtos, setProdutos] = useState([])

// objeto
const [aluno, setAluno] = useState({ nome: '', idade: 0 })
🎰
Lembra do "HookMegaSena" da Aula 02? Você usou exatamente isso: um useState guardando o último número sorteado, e outro guardando o array de números já sorteados. O segredo do espalhamento: [...arrayAntigo, novo].

Opção 1
📁 public/
logo.png

No JSX

Opção 2
📁 src/assets/
logo.png
precisa importar antes

Props e .map para listas
Aula 03 · Componente pai passando dados pro filho

Props (de "properties", propriedades) são os parâmetros que um componente pai passa para um componente filho. É como passar argumentos pra uma função.

É como mandar uma encomenda

O pai coloca os dados na caixinha (a tag JSX). O filho recebe a caixinha como parâmetro (props) e abre pra ver o que tem dentro.

Aluno.jsx · forma 1 (props inteiro) JSX 
const Aluno = (props) => {
  return (
    <div>
      <h2>{props.nome}</h2>
      <p>Curso: {props.curso}</p>
    </div>
  )
}

export default Aluno

Mais moderno é desestruturar direto na assinatura — você fica sabendo, só de bater o olho, quais props o componente recebe:

Aluno.jsx · forma 2 (destructuring ⭐) JSX 
const Aluno = ({ nome, curso, email }) => {
  return (
    <div>
      <h2>{nome}</h2>
      <p>Curso: {curso}</p>
      <p>Email: {email}</p>
    </div>
  )
}

export default Aluno

E pra usar esse componente várias vezes a partir de uma lista, a gente usa .map() — que percorre o array e devolve um novo JSX pra cada item:

App.jsx · lista com .map JSX 
import Aluno from './components/Aluno';

const App = () => {
  const alunos = [
    { id: 1, nome: 'Ana',   curso: 'TI', email: 'ana@uniesp.edu.br' },
    { id: 2, nome: 'Bruno', curso: 'SI', email: 'bruno@uniesp.edu.br' },
    { id: 3, nome: 'Carla', curso: 'ADS', email: 'carla@uniesp.edu.br' },
  ];

  return (
    <div>
      {alunos.map((aluno) => (
        <Aluno
          key={aluno.id}
          nome={aluno.nome}
          curso={aluno.curso}
          email={aluno.email}
        />
      ))}
    </div>
  );
}
🔑
Sempre coloque uma key única em cada item do .map. Pode ser o id do objeto. Sem isso o React reclama no console e tem comportamentos estranhos. Nunca use o índice do array como key se a lista for mudar de ordem.

Renderização condicional e Fragments
Aula 03 · Mostrar uma coisa OU outra · agrupar sem div

Pra mostrar uma coisa ou outra dependendo de uma condição, a forma mais comum em JSX é o operador ternário:

Login.jsx · ternário JSX 
const Login = ({ logado }) => {
  return (
    <div>
      {logado
        ? <h1>Bem-vindo de volta!</h1>
        : <h1>Faça login</h1>}
    </div>
  );
}
Lendo o ternário em voz alta

condicao ? coisaSeForTrue : coisaSeForFalse

"Se logado é verdadeiro, mostra Bem-vindo. Senão, mostra Faça login."

Pra mostrar algo só se a condição for verdadeira (sem ter um "senão"), use o &&:

Carrinho.jsx JSX 
{quantidade > 0 && <p>Você tem {quantidade} itens</p>}

E os Fragments? Servem pra agrupar elementos sem criar uma div a mais no HTML final. Útil quando você precisa retornar mais de um elemento e não quer um pai desnecessário:

SemDiv.jsx JSX 
const SemDiv = () => {
  return (
    <>
      <h1>Título</h1>
      <p>Parágrafo</p>
    </>
  );
}

Esse <>...</> é a forma curta do React.Fragment. Você usa quando o componente precisa retornar mais de uma tag mas você não quer envolver tudo numa div que não tem propósito.

CSS no React
Aula 04 · 4 jeitos de estilizar

Tem 4 jeitos principais de colocar CSS num projeto React. Cada um tem seu uso, mas o CSS Modules é o mais recomendado pra evitar dor de cabeça.

🌐 CSS Global Estilos pro body inteiro. Fica em src/index.css.
📌 CSS Inline style={{ }} direto na tag. Útil pra um detalhe.
📄 CSS de Componente Import de .css + className. Mas vaza.
🛡️ CSS Modules ⭐ .module.css + styles.minhaClasse. Não vaza.

1️⃣ CSS Global — pra resets e tipografia. Já vem o index.css no projeto:

src/index.css CSS 
body {
  margin: 0;
  font-family: 'Arial', sans-serif;
  background: #f4f4f4;
}

h1 { color: #333; }

2️⃣ Inline — duas chaves, propriedades em camelCase:

Inline.jsx JSX 
<div style={{
  backgroundColor: 'blue',
  color: 'white',
  padding: '20px',
  borderRadius: '8px'
}}>
  Olá, mundo!
</div>
📝
No CSS normal escrevemos background-color. No inline do React vira backgroundColor (camelCase). Mesma coisa: font-size vira fontSize, border-radius vira borderRadius.

4️⃣ CSS Modules ⭐ — a forma mais segura. Cada componente tem seu CSS isolado:

Botao.module.css CSS 
.primary {
  background: #61dafb;
  color: #0a0a16;
  padding: 10px 20px;
  border: none;
  border-radius: 8px;
  cursor: pointer;
}
Botao.jsx JSX 
import styles from './Botao.module.css';

const Botao = () => {
  return (
    <button className={styles.primary}>
      Clique
    </button>
  );
}
🛡️
Por que CSS Modules é melhor? Se em dois componentes você criar uma classe .botao, num CSS comum elas conflitam. Com Modules, o React gera nomes únicos por baixo dos panos (Botao_primary_x7g2k), então nunca dá conflito.

Dá também pra trocar de classe dinamicamente com base num estado, usando ternário no className:

TemaApp.jsx JSX 
<div className={escuro ? styles.dark : styles.light}>
  Olá!
</div>

Formulários com useState
Aula 04 · onChange · onSubmit · controlled inputs

No React, o jeito recomendado de fazer formulário é o chamado "input controlado": cada campo tem um useState, e o valor que aparece no campo sempre vem do estado. Quando o usuário digita, o onChange atualiza o estado, que redesenha o input.

É um vai-e-vem constante

Você digita → onChange dispara → estado muda → React redesenha o input com o novo valor → você vê o que digitou. Parece complicado, mas é só esse ciclo repetindo a cada tecla.

CadastroAluno.jsx JSX 
import { useState } from 'react';

const CadastroAluno = () => {
  const [nome, setNome] = useState('');
  const [email, setEmail] = useState('');

  const handleSubmit = (e) => {
    e.preventDefault();  // evita o F5 da página
    console.log('Enviando:', { nome, email });
    alert(`Cadastrado: ${nome}`);
  }

  return (
    <form onSubmit={handleSubmit}>
      <label>
        Nome:
        <input
          type="text"
          value={nome}
          onChange={(e) => setNome(e.target.value)}
        />
      </label>

      <label>
        Email:
        <input
          type="email"
          value={email}
          onChange={(e) => setEmail(e.target.value)}
        />
      </label>

      <button type="submit">Enviar</button>
    </form>
  );
}
O segredo dos 3 atributos

🎯 value={nome} — o valor que aparece no input vem do estado

🔁 onChange={...} — toda vez que o usuário digita, atualiza o estado

📨 onSubmit={...} — quando aperta enviar, dispara a função (com preventDefault!)

🛑
Sempre e.preventDefault() no submit! Senão o navegador recarrega a página inteira (comportamento padrão de HTML antigo) e seu React é apagado.

useEffect — o irmão executor do useState
Hook que executa código em momentos específicos
🆕
Não foi visto em sala — apareceu de raspão na Aula 06 junto com o Axios, mas não deu tempo de praticar direito. Vamos com calma agora. Spoiler: é mais simples do que parece.

Você já conhece o useState: ele guarda um valor. O useEffect é o irmão dele que faz outra coisa: ele executa um pedaço de código em momentos certos da vida do componente.

Pensa numa caixa de surpresa

O useState é a gaveta onde você guarda valores. O useEffect é o robô que liga sozinho quando a gaveta aparece (componente "nasceu" na tela) ou quando alguém mexeu nela (estado mudou).

Em React a gente chama esses "momentos da vida do componente" de ciclo de vida. O useEffect é como você pendura código nesses momentos.

PrimeiroEfeito.jsx JSX 
import { useEffect } from 'react';

const PrimeiroEfeito = () => {
  useEffect(() => {
    console.log('Oi! O componente acabou de aparecer na tela.');
  }, []);

  return <h1>Página carregou!</h1>;
}
A anatomia do useEffect

useEffect(função, array)

📦 função — o código que vai rodar (entre () => { ... })

🎯 array — diz quando rodar. Esse é o segredo:

[ ]  → roda 1 vez só, quando o componente aparece
[contador]  → roda quando o componente aparece E sempre que contador muda
(sem array)  → roda em toda renderização (cuidado, pode dar loop infinito!)

Pra 99% dos casos práticos (incluindo todos os nossos desafios), você vai usar o useEffect(...) com array vazio [] — significa "roda uma única vez, quando a página/componente carrega". É exatamente o que a gente quer pra buscar dados de uma API:

CarregarDados.jsx · padrão clássico JSX 
import { useState, useEffect } from 'react';

const CarregarDados = () => {
  const [produtos, setProdutos] = useState([]);

  useEffect(() => {
    // aqui vai entrar a chamada ao back-end (axios.get)
    console.log('Buscando produtos do back-end...');
    // setProdutos(dadosQueVoltaram);
  }, []);

  return (
    <ul>
      {produtos.map((p) => <li key={p.id}>{p.nome}</li>)}
    </ul>
  );
}
⚠️
O array de dependências NÃO é decoração. Esquecer o [] faz o useEffect rodar em toda renderização. Se ele atualiza um estado, vira loop infinito e seu navegador trava. Sempre coloque o array, nem que esteja vazio.
🧠
Pra fixar: useState = guardar coisa que muda na tela. useEffect = executar código em algum momento. Eles trabalham juntos: o useEffect busca dados, e usa o useState pra guardá-los e mostrar na tela.

json-server — back-end fake em 1 comando
Transforma um JSON em uma API REST de verdade
🆕
Não foi visto em sala. Mas é um dos truques mais úteis pra praticar front-end sem depender de um back-end pronto. Em 5 minutos você tem uma API REST funcionando.

O json-server é uma ferramenta Node.js que pega um arquivo db.json qualquer e cria automaticamente uma API REST completa em cima dele — com GET, POST, PUT, DELETE funcionando de verdade.

🤔 Mas pra que serve um back-end fake?

No mundo real das empresas, a equipe de back-end e a de front-end trabalham em paralelo. Imagina se o front tivesse que esperar o back terminar pra começar as telas? A entrega ia atrasar meses, e a empresa perderia dinheiro à toa.

Por isso a galera do front usa um mock server (servidor de mentirinha): uma API REST falsa que se comporta exatamente igual à API real vai se comportar quando ficar pronta. O front faz as telas integradas com esse mock — chamadas HTTP de verdade, dados de verdade — e quando o back fica pronto, basta trocar a URL.

📦 É exatamente o que o json-server faz pra gente: simula o back-end inteiro a partir de um arquivo JSON. Nenhuma linha de Java/Spring necessária.

Vamos configurar passo a passo, do jeito que a galera faz no dia a dia:

1️⃣ Instalar o json-server no projeto

Em vez de só rodar com npx avulso, a gente instala como dependência de desenvolvimento. Assim o projeto inteiro fica auto-suficiente — qualquer pessoa que clonar o repositório, ao rodar npm install, já tem o json-server pronto.

Axios — quem faz a "viagem" até o back-end
3 verbos: get, post, delete
🆕
Apareceu na Aula 06 mas não deu tempo de praticar. É a biblioteca que faz o front conversar com o back. Junta com useEffect e json-server e você tem um CRUD funcionando.

O Axios é uma biblioteca JavaScript que faz requisições HTTP — ou seja, é quem efetivamente leva e traz dados entre seu React e o back-end (no nosso caso, o json-server).

Pensa no Axios como o motoboy

Seu componente React precisa de produtos do back-end. Ele chama o motoboy Axios: "vai lá no localhost:3001/produtos e me traz a lista". O Axios viaja, busca, e volta com os dados. Você guarda no useState e o React desenha na tela.

Pra mandar dados (cadastrar), é o contrário: você dá um pacote pro motoboy, ele leva pro back-end, e volta confirmando "entreguei".

React
seu componente
<-> axios
Internet
HTTP request
<->
Back-end
json-server

Instalação — dentro da pasta do seu projeto:

terminal · instalar axios TERMINAL 
npm install axios

E nos componentes onde você quer usar, importa no topo:

QualquerComponente.jsx JSX 
import axios from 'axios';

Agora os 3 verbos. Você vai usar esses 3 nos desafios:

🟢 axios.get — buscar dados

É a forma mais comum. Use dentro de um useEffect pra carregar dados quando o componente aparece na tela:

ExemploGet.jsx JSX 
import { useState, useEffect } from 'react';
import axios from 'axios';

const ListaProdutos = () => {
  const [produtos, setProdutos] = useState([]);

  useEffect(() => {
    axios.get('http://localhost:3001/produtos')
      .then((resposta) => {
        setProdutos(resposta.data);
      })
      .catch((erro) => {
        console.error('Deu ruim:', erro);
      });
  }, []);

  return (
    <ul>
      {produtos.map((p) => (
        <li key={p.id}>{p.nome} - R$ {p.preco}</li>
      ))}
    </ul>
  );
}
Por que resposta.data?

O Axios envolve a resposta num objeto com várias informações (status, headers, etc). Os dados que você quer ficam dentro de .data. Por isso setProdutos(resposta.data), não setProdutos(resposta).

🟡 axios.post — enviar dados (cadastrar)

Recebe dois argumentos: a URL e o objeto que você quer cadastrar. Use no onSubmit do formulário:

ExemploPost.jsx JSX 
const handleSubmit = (e) => {
  e.preventDefault();

  const novoProduto = { nome, preco };

  axios.post('http://localhost:3001/produtos', novoProduto)
    .then((resposta) => {
      alert('Cadastrado com sucesso!');
      console.log('O back devolveu:', resposta.data);
    })
    .catch((erro) => {
      alert('Deu ruim ao cadastrar :(');
    });
}
🎁
O json-server cria o id sozinho! Você manda só { nome, preco }. Quando a resposta voltar, ela já vai ter um id gerado automaticamente.

🔴 axios.delete — apagar

Recebe só a URL com o id do item que vai ser apagado:

ExemploDelete.jsx JSX 
function remover(id) {
  axios.delete(`http://localhost:3001/produtos/${id}`)
    .then(() => {
      alert('Removido!');
      // atualiza a lista local sem ter que recarregar tudo:
      setProdutos(produtos.filter((p) => p.id !== id));
    });
}
🔄
Atualizar a lista local depois de apagar. O back-end já apagou, mas seu useState ainda tem o item. Use o .filter pra criar um novo array sem aquele id: setProdutos(produtos.filter(p => p.id !== id)). Aí a tela atualiza sem precisar de F5.

Versão async/await (mais limpa)

Em vez de .then().catch(), dá pra escrever do jeito async/await, que parece mais com código normal:

VersaoAsync.jsx JSX 
useEffect(() => {
  async function buscar() {
    try {
      const resposta = await axios.get('http://localhost:3001/produtos');
      setProdutos(resposta.data);
    } catch (erro) {
      console.error(erro);
    }
  }
  buscar();
}, []);

Os dois jeitos funcionam igual. Nos desafios vou usar o .then().catch() porque é mais direto pra quem está começando, mas você pode usar o async/await se preferir.

import { useState } from 'react';
import axios from 'axios';

const CadastrarTarefa = () => {
  const [titulo, setTitulo] = useState('');
  const [descricao, setDescricao] = useState('');

  const handleSubmit = (e) => {
    e.preventDefault();

    const novaTarefa = { titulo, descricao };

    axios.post('http://localhost:3001/tarefas', novaTarefa)
      .then((resposta) => {
        alert('Tarefa cadastrada com sucesso!');
        console.log('Tarefa criada:', resposta.data);
        setTitulo('');
        setDescricao('');
      })
      .catch((erro) => {
        alert('Deu ruim ao cadastrar :(');
        console.error(erro);
      });
  }

  return (
    <div>
      <h1>Cadastrar Tarefa</h1>
      <form onSubmit={handleSubmit}>
        <label>
          Título:
          <input
            type="text"
            value={titulo}
            onChange={(e) => setTitulo(e.target.value)}
          />
        </label>
        <br />
        <label>
          Descrição:
          <input
            type="text"
            value={descricao}
            onChange={(e) => setDescricao(e.target.value)}
          />
        </label>
        <br />
        <button type="submit">Cadastrar</button>
      </form>
    </div>
  );
}

import { useState, useEffect } from 'react';
import axios from 'axios';

const ListaProdutos = () => {

  useEffect(() => {
    axios.get('http://localhost:3001/produtos')
      .then((resposta) => setProdutos(resposta.data))

            {produto.nome} - R$ {produto.preco}

            </button>

}

Por que .filter e não .splice?

O .filter cria um novo array. O React precisa de um array novo pra perceber a mudança e redesenhar a tela. Se você usasse .splice no array antigo, o React não detectava a mudança (a referência é a mesma).

Lê assim: "crie um novo array só com os produtos cujo id é diferente do que eu quero apagar".

⚠️
Atenção ao operador !== (três caracteres: !, =, =). Se sua IDE tiver ligatures ativas ele pode aparecer como ≠. Mas você precisa digitar os três caracteres separados.

import { useState, useEffect } from 'react';
import axios from 'axios';
import styles from './ListaRecados.module.css';

const URL = 'http://localhost:3001/recados';

const ListaRecados = () => {
  const [recados, setRecados] = useState([]);
  const [titulo, setTitulo] = useState('');
  const [mensagem, setMensagem] = useState('');
  const [carregando, setCarregando] = useState(true);

  // 1. BUSCAR (GET) ao montar o componente
  useEffect(() => {
    axios.get(URL)
      .then((resposta) => {
        setRecados(resposta.data);
        setCarregando(false);
      })
      .catch((erro) => {
        console.error(erro);
        setCarregando(false);
      });
  }, []);

  // 2. CADASTRAR (POST) ao enviar o formulário
  const handleSubmit = (e) => {
    e.preventDefault();
    const novoRecado = { titulo, mensagem };
    axios.post(URL, novoRecado)
      .then((resposta) => {
        // adiciona o novo recado na lista local (com o id que o back devolveu)
        setRecados([...recados, resposta.data]);
        setTitulo('');
        setMensagem('');
      })
      .catch((erro) => {
        alert('Erro ao cadastrar :(');
        console.error(erro);
      });
  }

  // 3. EXCLUIR (DELETE)
  const excluirRecado = (id) => {
    axios.delete(`${URL}/${id}`)
      .then(() => {
        setRecados(recados.filter((r) => r.id !== id));
      });
  }

  return (
    <div className={styles.container}>
      <h1 className={styles.titulo}>📝 Lista de Recados</h1>

      {/* FORMULÁRIO (POST) */}
      <form onSubmit={handleSubmit} className={styles.form}>
        <input
          type="text"
          placeholder="Título"
          value={titulo}
          onChange={(e) => setTitulo(e.target.value)}
          required
        />
        <textarea
          placeholder="Mensagem"
          value={mensagem}
          onChange={(e) => setMensagem(e.target.value)}
          required
        />
        <button type="submit" className={styles.botaoCadastrar}>
          Cadastrar
        </button>
      </form>

      {/* TERNÁRIO: mostra "Carregando..." ou a lista */}
      {carregando ? (
        <p className={styles.vazio}>Carregando...</p>
      ) : (
        <>
          {/* &&: mostra mensagem só se a lista estiver vazia */}
          {recados.length === 0 && (
            <p className={styles.vazio}>Nenhum recado ainda. Cadastre o primeiro!</p>
          )}

          {recados.map((recado) => (
            <div key={recado.id} className={styles.recado}>
              <div>
                <strong>{recado.titulo}</strong>
                <p>{recado.mensagem}</p>
              </div>
              <button
                className={styles.botaoExcluir}
                onClick={() => excluirRecado(recado.id)}
              >
                Excluir
              </button>
            </div>
          ))}
        </>
      )}
    </div>
  );
}

export default ListaRecados;
